# プロジェクトの目的と設計（唯一の基準）

作業の判断に迷ったら、まずここに戻る。ここに書かれていないことを足すときは、利用者に確認してから `docs/DECISIONS.md` に記録する。
「要確認」の項目は利用者が確定するまで仮置き。確定したら書き換える（日付つき）。

## 1. 目的

- つきそいサポート（通院・買い物・旅行などの付き添い）の**公式ホームページ**で、はじめての人が安心して**問い合わせフォームから相談する**ところまで迷わず進めるようにする。
- 参考サイト（travelbuddy.jp）の構成・導線・価格帯を揃えつつ、文章・写真・屋号は自前にする（`CLAUDE.md` 2）。

## 2. 成果の定義（これが良くなる変更を優先する）

1. 問い合わせへの到達: どのページ・どの位置からでも、1〜2 タップ／クリックで問い合わせフォームに着く。
2. 安心感: 初めての人が不安に思うこと（費用・安全・無理に勧誘されないか・何をしてくれるか）に、サイトの上で答えが見える。
3. 読みやすさ: 高齢の本人や疲れた家族がスマホで読める（文字サイズ・行間・コントラスト）。
4. 嘘をつかない: 未確定の情報を確定のように見せない（`CLAUDE.md` 1）。

数値目標（月の問い合わせ件数など）: **要確認**（利用者が決める。決まるまでは設けない）。

## 3. 想定する訪問者（初期案・要確認）

| 類型 | 状況 | 最初に知りたいこと |
|---|---|---|
| ①高齢の本人 | ひとりで出かけるのが不安 | 怖くないか、何をしてくれるか、いくらか |
| ②離れて暮らす家族 | 親の通院・買い物・旅行の付き添いを探している | 信頼できるか、費用、家族への報告はあるか |
| ③医療的ケア児の保護者 | 外出の付き添いを頼める人を探している | 対応できる範囲、事前の打ち合わせ |
| ④ケアマネ・相談員 | 利用者に紹介できる先を探している | 対応範囲、料金表、連絡方法 |

## 4. 提供内容（確定している範囲）

- 提供中のメニューと料金は `src/pages/service.astro` の `prices` が正。
- 福祉タクシー（許可）・旅行手配（登録）は取得を確認するまで「準備中」（`CLAUDE.md` 1）。

## 5. デザインの方向（北極星）

- 気持ち: あたたかく、静かで、信頼できる。派手にしない。「いつでも、そばに。」
- 色・フォントの実装は `src/styles/global.css` のトークンが正。新しい色は足さず、まずトークンで表現できるか確認する。
- 変更は上の「成果の定義」に効くものを優先し、見た目だけの好みで足さない。

## 6. スコープ外（今はやらない）

- 予約・決済・会員機能などの動的機能。問い合わせフォームのみ。
- 許認可が確認できていないサービスの案内の本格化。
- 数値目標が決まる前の細かなアクセス解析の設計。

## 7. 公開判断のゲート（利用者が判断する。Claude Code / Codex は公開しない）

公開（`SITE.PUBLISHED = true`、Production への反映）の前に、次がすべて満たされていること。

- [ ] 電話・住所・LINE・Instagram・メール・受付時間の実際の値の確定（`src/config.ts`）
- [ ] `PUBLIC_FORM_KEY` を Vercel に設定し、実際の送信を確認
- [ ] `/privacy` の正式な文面（「雛形・要確認」の表示を外す）
- [ ] 福祉タクシー・旅行手配の許可／登録の取得状況の確認と、表記の確定
- [ ] 写真・画像の権利、代表者プロフィール、連携団体の掲載承諾
- [ ] 全体監査（`docs/WORKFLOW.md` のゲート監査）で重大・中の指摘が 0
- [ ] 参考サイトとの本文照合の再実行

## 8. 利用者にだけ確認できること（Claude Code・Codex は仮の値で埋めない）

連絡先の実際の値、屋号の最終形、代表者の氏名・経歴・資格、許認可の状況、連携団体、実績・お客様の声、写真素材の権利、料金の最終額、数値目標。
